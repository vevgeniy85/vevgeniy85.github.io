# Задача: разработать адаптивное портфолио Web / E-commerce Developer

## 1. Цель проекта

Создай современный многостраничный сайт-портфолио веб-разработчика на основе описанной ниже дизайн-системы. На 3 язаках: EN / UA / RU

Название бренда: **Extended Solution**

Позиционирование: Web / E-commerce Developer. Разработка и доработка сайтов на WordPress и Shopify, создание адаптивных интерфейсов, кастомных тем и функциональности для электронной коммерции.

Сайт должен выглядеть как профессиональное портфолио разработчика, которому можно доверить коммерческий проект. Не используй типичный шаблон с огромным количеством градиентов, стеклянных карточек и декоративных элементов.

Главные приоритеты:

* Современный, минималистичный, технологичный дизайн.
* Качественная типографика и визуальная иерархия.
* Тёмный интерфейс с фиолетовыми акцентами.
* Аккуратные отступы и выверенная композиция.
* Полноценная адаптивность.
* Реальные многостраничные маршруты и работающая навигация.
* Чистый, понятный и поддерживаемый код.

## 2. Этап 1 — анализ проекта

Перед началом разработки:

1. Изучи структуру репозитория и существующие файлы.
2. Определи используемый стек, инструменты сборки, систему маршрутизации и соглашения проекта.
3. Проверь существующие компоненты, стили, изображения, шрифты и другие ресурсы.
4. Если проект уже существует, продолжай использовать его архитектуру и соглашения.
5. Не переинициализируй проект и не заменяй зависимости без необходимости.
6. Не удаляй существующий функционал, не связанный с задачей.

Если проект пустой, реализуй сайт на семантическом HTML, CSS и JavaScript без обязательного подключения тяжёлого фреймворка.

После анализа приступай к реализации. Не ограничивайся рекомендациями, планом или демонстрационным прототипом.

## 3. Дизайн-система

### Цветовая палитра

Используй следующие базовые цвета:

* Основной фон: #080B0F.
* Фон секций: #0C1117.
* Фон карточек: #0E141C.
* Границы: #222B36.
* Основной текст: #F1F4FA.
* Вторичный текст: #A0ADBF.
* Приглушённый текст: #6F7D90.
* Основной акцент: #A855F7.
* Акцент при наведении: #C084FC.
* Дополнительные цвета для небольших деталей: красный #FF4545, зелёный #42D392.

Фиолетовый — главный акцент. Красный и зелёный применяй дозированно: в небольших декоративных линиях, статусах или деталях иллюстраций. Не используй все акцентные цвета одновременно в каждом блоке.

### Типографика

Используй Inter или аналогичный современный гротеск.

* Основной текст: 14–16 px.
* Подписи: 12–13 px.
* Заголовки карточек: 18–22 px.
* Заголовки секций: 32–42 px на десктопе.
* Главный заголовок первого экрана: ориентировочно 48–64 px.
* Высота строки заголовков: 1.05–1.2.
* Высота строки основного текста: 1.5–1.75.

Размеры должны адаптироваться к ширине экрана. Не допускай слишком мелкого текста и чрезмерно длинных строк.

### Общие правила оформления

* Контейнер на десктопе: max-width около 1200 px.
* Горизонтальные отступы контейнера: 24–40 px.
* Расстояние между секциями: ориентировочно 80–112 px на десктопе.
* Скругление карточек: 10–14 px.
* Скругление кнопок: 999 px.
* Тонкие границы вместо тяжёлых теней.
* Фиолетовые акценты в активных ссылках, иконках, кнопках и небольших деталях.
* Минимум декоративных элементов.
* Не используй эмодзи вместо иконок.
* Не делай каждую секцию отдельной большой карточкой.
* Не используй цветные подложки для каждого заголовка.
* Не добавляй лишние анимации и параллакс.

Для иконок используй существующую библиотеку проекта, если она уже подключена. В противном случае допустимы Lucide или простые SVG-иконки.

## 4. Общая структура сайта

Создай следующие страницы:

1. Главная — `/`
2. Обо мне — `/about/`
3. Портфолио — `/portfolio/`
4. Страница отдельного проекта — `/portfolio/travel-agency/`

Все страницы должны иметь единый стиль, общую шапку, подвал, навигацию и дизайн-систему.

Если используемый стек предполагает другую систему маршрутизации, реализуй эквивалентные маршруты согласно архитектуре проекта.

## 5. Общие компоненты

### Шапка

Создай компактную шапку высотой примерно 64–76 px.

Слева:

* Текстовый логотип `Extended Solution`.
* Буква `Extended` выделена белым цветом.
* Буква `Solution` выделена красным цветом.

По центру:

* Главная.
* Обо мне.
* Услуги.
* Портфолио.
* Контакты.

Справа:

* Контурная кнопка «Написать мне» со стрелкой.

Требования:

* Активный пункт меню выделяется фиолетовым цветом и тонким подчёркиванием.
* Шапка должна корректно работать на всех страницах.
* На мобильных устройствах используй компактное меню с доступной кнопкой открытия и закрытия.
* Все ссылки должны вести на реальные страницы.
* Не используй `href="#"` для имитации навигации.

### Подвал

Содержимое:

* Логотип Extended Solution
* Краткая подпись `Web Developer / WordPress / Shopify / JavaScript`.
* Год в копирайте.
* Небольшая кнопка возврата наверх.

Не дублируй в подвале все секции сайта. Сделай его компактным и минималистичным.

### Кнопки

Основная кнопка:

* Фиолетовая заливка.
* Белый текст.
* Стрелка вправо.
* Небольшое изменение яркости при наведении.

Вторичная кнопка:

* Прозрачный фон.
* Тонкая граница.
* Светлый текст.

У всех интерактивных элементов должны быть состояния hover, focus-visible и active.

### Основной блок

Две колонки.

Левая колонка:

* Email.
* Telegram.
* Другие каналы связи, если они заданы.
* Предпочтительный способ связи, если он известен.

Все контактные данные должны задаваться в одном конфигурационном файле.

Правая колонка — форма обратной связи:

* Имя.
* Email.
* Тип проекта.
* Сообщение.
* Чекбокс согласия на обработку данных, если он требуется.
* Кнопка «Отправить сообщение».

Реализуй:

* Проверку обязательных полей.
* Валидацию email.
* Понятные сообщения об ошибках.
* Состояние отправки.
* Сообщение об успешной отправке только после реального подтверждения.

Не имитируй успешную отправку, если серверная обработка не настроена. Если в проекте нет backend или API, подготовь интерфейс формы и отдельный понятный адаптер для последующего подключения отправки.

Не собирай лишние персональные данные.

## 12. Адаптивность

Обеспечь корректную работу сайта на следующих ширинах:

* 1440 px и выше.
* 1024 px.
* 768 px.
* 375–430 px.

Правила:

* Не допускай горизонтальной прокрутки.
* На мобильных устройствах используй одноколоночные блоки там, где это необходимо.
* Карточки должны перестраиваться автоматически.
* Заголовки не должны выходить за пределы контейнера.
* Кнопки должны оставаться удобными для нажатия пальцем.
* Навигация должна корректно открываться и закрываться.
* Изображения должны сохранять пропорции и не искажаться.
* Формы должны полностью помещаться в экран.
* Не уменьшай весь десктопный сайт пропорционально до мобильного размера.

Используй CSS Grid и Flexbox там, где они подходят.

## 13. Изображения и графика

Изображения являются важной частью дизайна.

Правила:

* Не используй размытые изображения.
* Не увеличивай маленькие картинки до размеров крупных баннеров.
* Для превью проектов используй качественные скриншоты или подготовленные демонстрационные макеты сайтов.
* Не используй случайные фотографии вместо скриншотов сайтов.
* Если нужных изображений нет, создай временные локальные SVG-макеты с интерфейсами сайтов или используй уже имеющиеся ресурсы.
* Все изображения должны иметь подходящий `alt`.
* Используй `object-fit` там, где это необходимо.
* Для изображений ниже первого экрана включай ленивую загрузку.
* Не создавай изображения программно с помощью сложных CSS-эффектов, если проще использовать подготовленный ресурс.

## 14. Анимации и взаимодействие

Используй минимальные анимации:

* Плавное изменение цвета ссылок.
* Небольшой подъём карточек при наведении.
* Изменение состояния кнопок.
* Аккуратное появление мобильного меню.

Не делай:

* Длительных вступительных анимаций.
* Мигающих элементов.
* Постоянно движущихся фоновых эффектов.
* Анимаций, мешающих чтению.

Учитывай системную настройку `prefers-reduced-motion`.

Все интерактивные элементы должны действительно выполнять заявленные действия.

## 15. Качество кода

* Используй семантические HTML-элементы.
* Придерживайся существующих соглашений именования проекта.
* Если проект использует БЭМ, продолжай использовать БЭМ.
* Вынеси повторяющиеся цвета, размеры и другие параметры в CSS-переменные.
* Не дублируй одинаковые стили между страницами без необходимости.
* Создавай переиспользуемые компоненты для шапки, подвала, кнопок, карточек и CTA.
* Разделяй данные проектов и их представление.
* Не добавляй лишние зависимости.
* Не используй inline-стили без необходимости.
* Не оставляй отладочный код и неиспользуемые файлы.
* Не добавляй комментарии, которые лишь повторяют очевидное действие кода.
* Не используй фиктивные ссылки `href="#"`.
* Проверь корректность путей к изображениям и ресурсам.
* Добавь базовые SEO-метаданные и уникальные заголовки страниц.
* Обеспечь доступность элементов с клавиатуры и видимый фокус.

## 16. Производительность

* Минимизируй количество JavaScript там, где достаточно CSS.
* Не подключай библиотеки только ради простых эффектов.
* Оптимизируй изображения.
* Используй локальные ресурсы, когда это возможно.
* Избегай скачков вёрстки при загрузке изображений.
* Не загружай изображения всех проектов в максимальном разрешении без необходимости.

## 17. Порядок реализации

Выполняй работу последовательно:

1. Изучи проект и его архитектуру.
2. Подготовь общую дизайн-систему.
3. Реализуй общие компоненты и навигацию.
4. Создай главную страницу.
5. Создай страницу «Обо мне».
6. Создай страницу портфолио и фильтрацию проектов.
7. Создай страницу отдельного проекта.
8. Создай страницу услуг.
9. Создай страницу контактов и подготовь обработку формы.
10. Проверь адаптивность.
11. Проверь навигацию и все интерактивные элементы.
12. Запусти доступные проверки, сборку и тесты проекта.
13. Исправь найденные ошибки.

Не останавливайся после создания главной страницы. Не заменяй остальные страницы заглушками и не ограничивайся одним визуальным прототипом.

## 18. Критерии готовности

Считай задачу выполненной, когда:

* Все шесть страниц созданы.
* Страницы используют единую дизайн-систему.
* Все внутренние ссылки работают.
* Фильтры портфолио функционируют.
* Мобильная навигация работает.
* Формы имеют валидацию.
* Не существует горизонтальной прокрутки на мобильных устройствах.
* Нет битых изображений и ошибок в консоли, вызванных новой реализацией.
* Проект собирается существующими инструментами.
* Все основные блоки имеют законченный визуальный вид.
* Код можно поддерживать и расширять без переписывания всего сайта.

В завершение сообщи:

1. Какие файлы созданы и изменены.
2. Какие страницы реализованы.
3. Какие проверки выполнены.
4. Какие реальные данные или изображения нужно заменить.
5. Требуется ли дополнительная настройка backend для отправки формы.

**Главное требование:** не пытайся буквально воспроизвести низкокачественный скриншот. Используй это техническое задание как точную спецификацию структуры, визуального стиля и поведения. Создай аккуратный, цельный, современный сайт, который выглядит профессионально на больших экранах и мобильных устройствах.
